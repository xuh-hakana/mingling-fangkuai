# 联动功能归属（命令方块侧）

这是干什么的：2026-11-06 她要求「提词器与命令方块分离成两套，所有联动功能放命令方块侧」。本文件列清哪些功能归命令方块维护、ticiqi 侧怎么调用。**命令方块的代码一份未删、未改**。

依据：`总备份/遗留问题/交接-命令方块v2.md`（§7 v2.1 提词器独立客户端）、`总备份/遗留问题/命令方块-待办与缺口.md`（§3 C6）。

## 1 边界

| 算联动（归命令方块侧） | 不算联动（归 ticiqi 自己） |
| --- | --- |
| 两个软件互相配合、跨进程跳转、共用数据 | 需求库、体检、遗留问题、界面、导出文本 |
| 由命令方块侧维护，ticiqi 只调用 | 独立可跑，不读 `命令方块/` 任何文件 |

ticiqi 侧保留 `cb:reveal` 的「在系统文件管理器定位」实现：这是独立客户端没有文件视图时的兜底，不是联动；联动版（跳到命令方块窗口）归命令方块侧。

## 3 已知风险（如实标注）

- **共用 `prompts.json`**：命令方块侧的提词器与 ticiqi 提词器若**同时打开**，两个进程都跑剪贴板采集轮询，会同时写同一份 json（`交接-命令方块v2.md` §7 坑 3 已记）。端口文件已分开（`port` / `port-prompter` / `port-ticiqi`），数据文件仍共用。是否给 ticiqi 独立数据目录，已登记 `ticiqi/需求/遗留问题/issue_001.md`，等她回复。
- **两套代码并存**：她原话「两套。没有命令方块的电脑提词器也能独立使用。但不要删命令方块侧的代码，最后还是要一起使用的。」因此提词器代码现在有两份，改一边另一边不会跟着变。这与 `交接-命令方块v2.md` §2.1 里「不能有双份代码」的旧约定不同，**以本轮她的话为准**。
- **Windows 未真机验收**：`命令方块-待办与缺口.md` §2.2 仍成立。ticiqi 的 `.bat` 会自动 `npm install electron`，本机未验证。
