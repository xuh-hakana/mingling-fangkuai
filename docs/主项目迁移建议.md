# 主项目【虚幻酱】迁入 Mac 的建议位置与目录结构

> 本文只给建议。本轮不迁移、不修改主项目文件，也不创建主项目目录。

## 1. 建议位置

| 内容 | 建议路径 | 说明 |
| --- | --- | --- |
| 主项目代码 | `~/Projects/xuwu-chan/` | 用英文目录名，避免命令行、压缩包和跨平台工具在中文路径上出现编码差异；项目显示名仍可写“虚幻酱”。 |
| 命令方块 | `~/Tools/command-block/` | 工具和主项目分开，避免工具更新混进主项目提交。 |
| 提词器（后续） | `~/Tools/prompt-tool/` | 与命令方块同级，方便互相接入，但不互相写入。 |
| 真实运行数据 | `~/Library/Application Support/XuwuChan/` | 记忆库、会话、真实日志等不放进 Git 仓库。 |
| 日志 | `~/Library/Logs/XuwuChan/` | macOS 惯例位置，便于按大小清理。 |
| 缓存/模型 | `~/Library/Caches/XuwuChan/` | 可随时重建的内容。 |
| 密钥 | 主项目根目录 `.env`（`chmod 600`） | 不只放 `src/` 里面；必须加入 `.gitignore`，另存一份到密码管理器。 |

不建议把主项目放在 `Desktop`、`Documents` 或 iCloud Drive 下：这些位置可能被 iCloud 同步，密钥、日志和记忆库容易意外上传，也会让文件监听和扫描变慢。

## 2. 推荐目录结构

```text
~/Projects/xuwu-chan/
├── README.md
├── pyproject.toml              # 或 package.json；只保留实际使用的那个
├── .env.example                # 只写变量名和空值
├── .env                        # 真实密钥；chmod 600；绝不提交
├── .gitignore
├── .gitattributes              # 统一 LF，避免 Windows/Mac 换行冲突
├── src/
│   └── xuwu_chan/
│       ├── __init__.py
│       ├── app.py              # 启动入口，只负责组装
│       ├── config.py           # 读取环境变量与路径
│       ├── core/               # 对话循环、状态机、调度
│       ├── persona/            # 人格维度、语气、边界、场景配置
│       ├── memory/             # 按人分类的记忆、检索、摘要
│       ├── platforms/
│       │   ├── qq/             # 第一个平台适配层
│       │   └── bilibili/       # 后续平台，先留空接口
│       ├── features/           # 陪聊、情感、技术内容等业务能力
│       ├── tools/              # 内部工具接口（提词器、命令方块等）
│       └── web/                # 若需要本地管理页；没有就删掉
├── tests/
│   ├── unit/                   # 纯函数、解析、记忆读写
│   ├── contract/               # 平台适配层契约测试
│   ├── scenario/               # 限定场景的可验收用例
│   └── evals/                  # 人格维度、评分表、失败回流样本
├── data/
│   ├── fixtures/               # 可提交的脱敏测试数据
│   └── demo/                   # 演示数据；真实记忆不在这里
├── docs/
│   ├── architecture.md
│   ├── persona-dimensions.md
│   ├── acceptance-scenario.md
│   └── data-flow.md            # 提词器/命令方块如何被主项目消费
├── scripts/
│   ├── dev.sh
│   └── test.sh
└── tools/
    └── README.md               # 只写外部工具的路径约定，不复制工具源码
```

真实运行数据不要放进 `data/`。`data/` 只存脱敏 fixture 和演示数据；真实记忆、会话、日志走 `~/Library/Application Support/XuwuChan/`。这样命令方块扫描项目时不会把真实聊天记录当成源码展示。

## 3. Windows → Mac 的搬迁顺序（以后执行）

1. **先备份**：Windows 上把项目打成 zip，排除 `.venv/`、`node_modules/`、`__pycache__/`、`dist/`、`build/`、`*.log`、`.env` 和任何密钥文件。
2. **单独传密钥**：`.env` 不走普通压缩包/聊天软件。用密码管理器或加密盘，搬到 Mac 后重新 `chmod 600 .env`；怀疑泄露就换 Key。
3. **放到 `~/Projects/xuwu-chan/`**：解压后确认中文文件名正常，检查只有大小写差异的重名文件（macOS 默认不区分大小写）。
4. **重建环境**：Windows 的 Python venv 不能直接复用。Mac 上用 Python 3.12 新建 `.venv`，重新 `pip install`；Node 项目删除 `node_modules` 后重新 `pnpm install`。
5. **统一换行**：`.gitattributes` 设定 `* text=auto eol=lf`，避免脚本出现 `\r`。
6. **先跑测试再跑平台**：按 `unit → contract → scenario` 顺序跑；第一轮不要接 QQ/B 站，保持“限定场景的可验收定义”。
7. **验证只读工具**：在命令方块里打开 `~/Projects/xuwu-chan/`，确认 `.env`、日志、缓存、构建目录没有出现在文件树中。
8. **迁移真实数据**：记忆库、会话、日志按“先副本、后切换”的方式放入 `~/Library/Application Support/XuwuChan/`，确认可读后再停 Windows 端。

## 4. 与命令方块、提词器的边界

- 命令方块只读 `~/Projects/xuwu-chan/`，不写主项目；收藏夹和 API 配置在命令方块自己的配置目录。
- 提词器后续从主项目的 `docs/`、测试集和可见 AI 输出中读取需求与评分材料；真实密钥和聊天原文不进入提词器。
- 主项目的失败案例回流到 `tests/evals/failures/`（脱敏），再由提词器或人工整理进测试集。
- 三个项目各自独立更新；需要共享的只有路径约定和脱敏数据格式，不复制同一份代码。
